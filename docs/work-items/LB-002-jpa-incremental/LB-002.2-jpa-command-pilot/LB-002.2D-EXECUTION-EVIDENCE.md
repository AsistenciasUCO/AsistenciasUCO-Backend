## Hash policy — CANONICAL_TEXT_SHA256

Definición: leer el contenido textual del archivo, normalizar únicamente `\r\n` → `\n` (sin trim, sin
tocar trailing spaces/tabs/encoding), y calcular SHA-256 sobre ese contenido normalizado. Para
archivos binarios se usa SHA-256 raw. La normalización ocurre solo para el cálculo; el archivo en
disco no se reescribe.

### Hash incident — `JpaAttendanceStoredProcedureFeasibilityIT.java`

- **RAW_CRLF_SHA256:** `145ac6f4c9177112bacfef449746fbe8e36f1d2274950176603f2675f214b054`
- **CANONICAL_LF_SHA256:** `b96b944c0c85801b690ec2c79f3d3df9894ffceeda4951938523f3830bb94be2`
- **Causa:** el archivo en disco tiene finales de línea Windows (CRLF); el hash congelado histórico
  (`b96b944c...`) se calculó sobre el contenido con LF. No hay mutación semántica: el mismo contenido
  normalizado produce exactamente el hash histórico.
- **Semantic mutation:** NO.
- **Human decision:** STOP LIFTED. No se restauró ni se modificó el archivo. El hash frozen histórico
  (`b96b944c...`) sigue siendo válido y **no fue reemplazado**; solo se documenta que el archivo físico
  usa CRLF y que el criterio de comparación en adelante es `CANONICAL_TEXT_SHA256`.
- **Regla futura:** todo hash frozen de un archivo de texto de este work item se calcula y compara con
  `CANONICAL_TEXT_SHA256`, nunca con el hash raw de bytes cuando el único cambio es el final de línea.
