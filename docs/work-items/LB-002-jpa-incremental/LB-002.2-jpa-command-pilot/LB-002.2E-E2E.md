## Alcance

Dejar el perfil `local` configurado para que, con `SPRING_PROFILES_ACTIVE=local` y sin variables de
entorno adicionales:

- `asistencia-query-provider = jpa` (sin cambio; vigente desde LB-002.1B).
- `asistencia-command-provider = jpa`, exclusivamente para `registrarAsistenciasSesion` (único
  command en alcance de LB-002.2; los demás commands de `Asistencia` siguen en JDBC, sin cambio en
  el Composition Root).

El perfil `dev` y el default global/sin perfil **no** cambian: siguen en `command=jdbc`. Esta tarea
no decide activación en `dev`; esa decisión queda fuera de LB-002.2E.

## Validación mínima ejecutada

Solo tests unitarios de Composition Root/configuración de providers (sin `clean verify`, sin
`-Pintegration`, sin SQL Server real):

```text
mvnw.cmd -Dtest=AsistenciaQueryProviderActivationTest,AsistenciaCommandProviderCompositionRootTest,
AsistenciaCommandProviderCharacterizationTest,JpaCapabilityRequiredConditionTest,
SqlServerPersistenceCompositionRootTest,AsistenciaCommandProviderAcceptanceRedTest,
AsistenciaQueryProviderCompositionRootTest test
```

Resultado: `BUILD SUCCESS`, exit code 0. Confirma con configuración REAL (`ConfigDataApplicationContextInitializer`
+ `spring.profiles.active=local`) que:

- `asistencia-query-provider` resuelve a `jpa`.
- `asistencia-command-provider` resuelve a `jpa` y `registrarAsistenciasSesion` enruta al candidato
  JPA (`AsistenciaJpaCommandPersistence`), sin invocar el JDBC del lote.
- El bean `AsistenciaRepositoryPort` se construye una sola vez, sin conflicto de beans ni de `EntityManagerFactory`
  (`JpaCapabilityRequiredCondition` sigue resolviendo un único EMF cuando cualquiera de los dos
  selectors es `jpa`).
- `dev` y sin perfil conservan `command=jdbc` sin cambio de comportamiento.
- El rollback explícito (`APP_ADAPTERS_PERSISTENCE_ASISTENCIA_COMMAND_PROVIDER=jdbc`) sigue ganando
  sobre el perfil `local`.

No se ejecutó `clean verify` ni la suite `-Pintegration`. No se hizo arranque completo del proceso
(`spring-boot:run`) contra SQL Server real. Esto es preparación de runtime, no certificación E2E.
